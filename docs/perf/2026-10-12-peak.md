## Reading

`docs/aws.md` sizes 100,000 receipts a day as about 1.2 receipts a second on average and about 12 at a 10x peak, on Aurora PostgreSQL and Fargate. This run used SQLite on one machine: SQLite serialises writes (`BEGIN IMMEDIATE`), every worker process shares the same file, and the client, the API and the workers share this machine's CPU. The figures say how the application behaves here, not how the AWS design would; where they miss, the limit named above is SQLite or this machine before it is the code. The simulated classifier answers every line the same way, so only timings matter. The profile used 10 worker process(es); one worker handles a receipt in about (lines x latency) seconds, so the worker count is what bounds the drain time.

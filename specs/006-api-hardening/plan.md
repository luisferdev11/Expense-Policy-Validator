# Implementation Plan: API hardening

**Branch**: `feat/006-api-hardening` | **Date**: 2026-10-12 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/006-api-hardening/spec.md`; decisions in
[research.md](research.md) (R1 to R15), tables in [data-model.md](data-model.md), API and CLI in
[contracts/api-delta.md](contracts/api-delta.md).

## Summary

Five slices on the iteration-3 backend, with no change to the engine:

1. A real migration mechanism (schema 1 → 2) and a **classification cache table** behind a new port,
   seeded from the committed JSONL and exportable back to it byte for byte; the budget counts per
   process. Several workers can share one database.
2. **`created_at`** on every receipt (revision 1's time, written once), one timestamp format across
   the store, and `order=` on the list.
3. **`decided_by` / `decided_at`** in the projection, set by a pure domain rule in the same
   transaction as the state change, backfilled from events.
4. **Typed `receipt` and `result`** in OpenAPI from the domain models, and TypeScript types generated
   from the committed document with a staleness test.
5. A **Locust load test** with four profiles, a simulated classifier with latency, and a report
   generator that writes `docs/perf/` with every figure's N.

## Technical Context

**Language/Version**: Python 3.12 (uv); TypeScript 5.6 for the front end

**Primary Dependencies**: existing FastAPI, pydantic 2, stdlib `sqlite3`; new dev dependency
`locust` (pin the version `uv add --dev` resolves, at least two weeks old, record it here at
implementation time); new front-end dev dependency `openapi-typescript` (exact 7.x version, at least
two weeks old, recorded here)

**Storage**: the same SQLite file (`var/epv.sqlite3`); schema version 2

**Testing**: pytest, test first for every deterministic part (migration, decision rule, cache
adapters, timestamp helper, ordering, report generator). Contract tests through `TestClient`. A
two-worker test in one process with two `Worker` instances over one database file. Vitest for the
generated-types staleness check. The load test itself is not part of `pytest`; a smoke test runs the
locustfile's task functions once against `TestClient` (no Locust runner) and the report generator on
a committed fixture CSV.

**Target Platform**: Linux, macOS; one machine

**Project Type**: web service plus worker plus React front end, in the existing layered package
(ADR 0003)

**Performance Goals**: measured, not enforced (research R14): at `nominal`, read p95 under 300 ms,
submit p95 under 500 ms, the worker keeps up with 1.5 s simulated latency per line

**Constraints**: labels firewall; engine untouched (alert Luis before any change under
`src/expense_validator/domain/engine/`); `epv run` and committed outputs byte-identical; Langfuse never
gates; everything in English

**Scale/Scope**: thousands of receipts per database for the load test; 78 seeded cache rows

## Delivery order (vertical slices)

Each slice ends with ruff, mypy and pytest green and one commit; cut from the bottom if time runs
out.

0. **Setup**: version 1.1.0 in `pyproject.toml`, `frontend/package.json`, `create_app`; Locust and
   openapi-typescript added.
1. **Migration framework and cache table (US1)**: schema 2 skeleton, `MIGRATIONS`, the port, both
   adapters, seed, export, budget per process, two-worker test.
2. **`created_at` and timestamps (US2)**: `stamp()`, write-once `created_at`, migration backfill,
   `order=`, batch `created_at`.
3. **Decision fields (US3)**: `decision_after`, wiring in the four write paths, backfill.
4. **Typed OpenAPI and generated types (US4)**: schemas, request body, regenerated document,
   front-end generator and tests, Postman.
5. **Load test (US5)**: simulated classifier and CLI options, `/health` `open_work`, locustfile,
   profiles, report, the `smoke` run committed, then `nominal` and `peak`.
6. **Polish**: AI_NOTES entry, quickstart verified, roadmap line, full verification.

## Risks

- **FastAPI's handling of frozen models with `extra="forbid"` as response fields.** If a schema name
  or mode surprises, keep the domain models and add thin response aliases in `schemas.py`; the wire
  format must not change (checked by parity and the front end's e2e).
- **SQLite write contention with several workers.** Short per-row cache transactions and the existing
  10 s busy timeout; the two-worker test and the `peak` profile measure it. The report says plainly
  if SQLite is the bottleneck (it is the expected limit; ADR 0009 moves to Aurora).
- **Budget semantics change** could surprise a long-running worker: the cap now resets per process.
  Documented in quickstart and AI_NOTES.
- **Engine change creeping in**: none is needed; stop and alert Luis if any test suggests otherwise.
